# JsVideoAnalyticsViewer

Браузерный клиент для серверов Video Analytics. Поддерживает авторизацию,
просмотр JPEG-кадров, запуск и остановку потока, запись исходного потока,
выбор камеры, PTZ, HLS-конфигурацию, настройку движения/сопровождения/YOLO,
загрузку ONNX и просмотр истории.

В истории сопровождения Motion ID и ID распознавания Tracking-YOLO показаны в
разных колонках; числовой Motion ID от Python нормализуется к виду `track-N`,
как у Clang и Rust. В обеих таблицах истории доступны серверные фильтры по
области, одной дате и одному часовому интервалу; текущая дата подставляется
автоматически. Щелчок по
заголовкам «Область», «Время обнаружения», «Продолжительность» и «Дата» меняет
поле и направление сортировки; фильтры передаются Clang Server как
query-параметры существующего `GET /history`.

В списке типов источника оставлены IP-камера и видеофайл. Синий светодиод
показывает подключение к Server, ярко-красный — активную запись.

JPEG-просмотр ограничен частотой 15 кадров/с и рисует кадры в одном canvas.
HLS воспроизводится локальной копией hls.js через защищённый путь `/hls/` без
серверного iframe и без обращения к внешнему CDN; буфер ограничивается и полностью
пересоздаётся раз в десять минут для освобождения памяти Chromium.
Разрешение и частота 15/30 FPS выбираются независимо. FPS меняется только
администратором через отдельный список: переключение HLS, загрузка страницы и
смена разрешения не подбирают частоту автоматически.

Текущая версия вьювера указана в `package.json`. История изменений вьювера
ведётся в [Release notes](ReleaseNotes.txt). Подробное учебное описание Node.js,
браузерного event loop, REST, JPEG/HLS и истории находится в
[документе по архитектуре](Architecture.md). Версия для чтения и печати:
[PDF](output/pdf/JsVideoAnalyticsViewer-Architecture.pdf). То же содержание,
распределённое по разделам ГОСТ 19.402-78 без форматки ЕСПД:
[описание программы](output/pdf/JsVideoAnalyticsViewer-Program-Description-GOST-19.402-78.pdf).
Практическое руководство по работе Viewer с Clang Server, включая скриншоты,
диапазоны параметров и цвета аналитических рамок:
[руководство пользователя](docs/user-guide-clang/README.md).

## Запуск

Требуется Node.js 18 или новее.

```powershell
npm start
```

Откройте `http://127.0.0.1:5173` и укажите учётные данные. Адрес REST задаётся
при запуске переменной `DEFAULT_SERVER_URL`, адрес HLS — `HLS_SERVER_URL`;
браузер не может изменить эти upstream. Для строгой проверки TLS задайте
`STRICT_TLS=1`.

Пароль и Bearer-токен хранятся только в `sessionStorage` текущей вкладки и
удаляются после её закрытия. HLS-плейлист и каждый сегмент требуют тот же токен.

## Docker на Ubuntu 24.04

Viewer собирается на базовом образе `ubuntu:24.04` с системным Node.js и
запускается от непривилегированного пользователя. Из общего каталога запуска:

```powershell
C:\work\settings\run-js-docker.ps1 -Build
```

В общем Docker-контуре откройте `http://127.0.0.1:15173`. REST и HLS доступны
на loopback-портах `18080` и `18888`, а Viewer обращается к контейнеру Server
по фиксированным именам внутри Compose-сети.

Для строгой проверки TLS подключённого Server используйте
`-StrictTls`. Остановить Viewer можно командой:

```powershell
C:\work\settings\stop-js-docker.ps1
```

Название вкладки содержит имя, версию и дату выпуска Viewer. Шапка интерфейса
после входа показывает имя, версию и дату выпуска реализации Server из
`/api/v1/health`, а также адрес текущего подключения. Даты отображаются в
формате `ДД.ММ.ГГГГ`.

Viewer учитывает роль, возвращённую Server. Для роли `viewer` отображаются все
вкладки, поля и управляющие элементы административного интерфейса. Визуально
блокируются только кнопки «Сохранить». Сервер при этом остаётся окончательной
границей безопасности и запрещает роли `viewer` изменяющие REST-команды с
ответом HTTP `403`, независимо от состояния интерфейса клиента.

Кнопка «Запись» расположена рядом с кнопкой «Запустить». Увеличенный красный
светодиод показывает активную запись, а надпись кнопки меняется на
«Остановить». Светодиод подключения к Server также увеличен. Соседний
список задаёт длительность отдельных
файлов: 10, 15, 30 или 60 минут; по умолчанию выбран один час. Управление
записью доступно роли `admin`. ClangVideoAnalyticsServer сохраняет файлы в
`C:\work\settings\files` с датой, временем и названием потока `camera_ptz`,
`panoramic` или `camera` в имени без миллисекунд.

При типе источника «Видеофайл» Viewer не открывает локальный диалог выбора.
После подключения он запрашивает `GET /api/v1/recordings/files` и показывает
в комбобоксе записи из серверной папки `files` вместе с размером. Кнопка
«Запустить» передаёт только имя выбранного файла в `POST /api/v1/stream/file`;
дальнейшее чтение кадров и видеоаналитика выполняются на Server.

Остановка записи не останавливает и не перезапускает видеопросмотр. Server
сразу подтверждает запрос, Viewer кратко показывает «Остановка…», а обычный
MP4 закрывается фоновым worker и после этого доступен для VLC.

ClangVideoAnalyticsServer использует один RTSP-сеанс камеры для просмотра,
аналитики и записи. Рекордер получает исходные кадры до наложения рамок и
кодирует их в H.264/MP4 без второго подключения к камере.
