# Тестирование и развёртывание

## Проверка API

C++, Python и Rust серверы проверяются по общему REST-контракту. Тесты охватывают авторизацию, роли, конфигурацию камер, защиту реквизитов, управление потоком, параметры истории, запись, PTZ и диагностические маршруты.

Python-реализация дополнительно содержит модульные тесты детектора движения, трекера, YOLO workers, истории событий, HLS, записи и профилировщика.

## Профилирование

Серверы собирают длительности отдельных этапов и счётчики потока:

- чтение и восстановление RTSP;
- Motion и Tracking;
- полный YOLO inference;
- YOLO для сопровождаемых целей;
- подготовка JPEG и HLS;
- число принятых, обработанных и отброшенных кадров;
- фактический FPS и глубина очередей.

Одинаковый k6-сценарий используется для сравнения REST-части C++, Python и Rust серверов. Результаты сохраняются в машинно-читаемом формате и в сводной таблице.

## Windows

C++ сервер собирается нативно с Clang и CMake. Зависимости управляются через vcpkg и отдельные SDK OpenCV и ONNX Runtime. Клиент разработан на JavaScript; Node.js 18 раздаёт статические файлы и проксирует разрешённые запросы к REST API и HLS.

## Docker и Ubuntu

Контейнерная сборка ориентирована на Ubuntu 24.04. Docker Compose объединяет сервер, клиент и PostgreSQL. Настройки, модели, записи и журналы подключаются как отдельные тома и не входят в образ.

Для эксплуатационной диагностики предусмотрены health endpoint, ограниченная ротация журналов и счётчики ошибок видеопотока.

## Переносимость

Архитектура отделяет захват и аналитику от REST API и пользовательского интерфейса. Благодаря этому один и тот же сценарий работает в нативной Windows-сборке и в Linux-контейнере.

## Публичный VPS

Публичный стенд работает через [alex-video-analytics.ru](https://alex-video-analytics.ru/). VPS предоставляет HTTPS-доступ к JavaScript-клиенту, REST API и HLS-потоку. Внутренние сервисы и адреса камер остаются за публичным контуром.
